SC-200 cheat sheet 1/5 — Microsoft Defender XDR

One page. Facts snapshot 2026-11; verify current behaviour on Microsoft Learn before the exam.

Portal, incidents, and identity of things

ItemWhat to remember
What XDR isThe correlation layer over Defender for Endpoint, Identity, Office 365, Cloud Apps (and Cloud). It joins alerts that share entities into one incident.
Alert vs incidentAn alert is one detection. An incident groups related alerts and carries status, owner, classification, and the attack story.
Queue defaultShows incidents from the last 30 days, newest first. Filters: status, severity, assignment, service source, tags, classification.
Incident tabsAttack story (timeline and evidence) · Alerts · Entities · Evidence and response · Summary · Similar incidents.
Lifecycle fieldsStatus (Active / Resolved) · Owner · Classification (true positive, false positive, informational, unknown) · Determination and reason.
Attack disruptionAutomatic containment from high-fidelity signals, for example disabling a compromised account or containing a device before an analyst acts.
Unified RBACOne role model across the Defender workloads: Security Reader < Security Operator < Security Administrator. Configured once in the Defender portal.
Threat analyticsCurated intelligence on tracked actors and campaigns, your exposure to their techniques, and related incidents.
Exposure managementContinuous attack-surface, exposure score, choke points, and attack paths before an incident occurs.
Security CopilotEmbedded assistance: incident summary, impact analysis, guided response, query drafting. It drafts; the analyst approves.

Advanced hunting and custom detections

ItemWhat to remember
Data windowUp to 30 days of raw data in the XDR schema (endpoint, email, identity, cloud app tables).
Versus SentinelNeed 90 days, custom tables, or workspace joins? Query in Sentinel, not advanced hunting.
Query languageKQL, same syntax as Sentinel, different table set. Device, Email, Identity, CloudApp, AlertInfo, AlertEvidence.
Custom detectionHunting query + schedule + optional response action (isolate device, mark user compromised, quarantine file, collect package).
Schedule optionsEvery 1, 3, 12, or 24 hours; a new rule first checks the past 30 days.
LimitsUp to 500 custom detections per tenant; each run is capped in time and results.
IndicatorsCustom file hash / IP / URL / certificate indicators with allow, alert, or block. Blocked hashes stop execution tenant-wide.

Defender for Endpoint

ItemWhat to remember
CoverageDevice inventory: onboarding status, OS, risk, exposure, vulnerabilities. Default view is alerts in the last 30 days.
DiscoveryDevice discovery finds unmanaged devices from network telemetry; standard or basic discovery mode.
IsolationFull blocks all network traffic except the Defender service; selective allows only listed destinations. Device stays manageable and live-response capable.
Live responseInteractive remote shell: dir, cd, getfile, putfile, run, analyze, remediate, library scripts. Session is audited.
Investigation packageZipped forensic snapshot: processes, network, autoruns, scheduled tasks, registry, event logs. Collect before rebuild.
ASR rulesBehaviour blocking for Office child processes, script/download chains, LSASS credential theft, USB untrusted executables. Audit first, then Block.
Tamper protectionBlocks local and GPO/registry attempts to disable antivirus, real-time protection, cloud protection, behaviour monitoring.
Device groupsGroup devices by tag/OS/domain and set the automation level: full remediation, semi (approval), or none.
AIRAutomated investigation reviews alerts, collects evidence, and proposes or performs remediation per the group's automation level; approvals land in Action center.
TVMThreat and vulnerability management prioritises by exposure + exploitability + threat intelligence, not by CVE age.
Other controlsWeb content filtering, network protection, EDR in block mode, controlled folder access, device control.

Defender for Identity

ItemWhat to remember
Sensor placementDomain controllers, plus AD FS, AD CS, and Microsoft Entra Connect servers. One sensor per server; no sensor means no visibility for that DC.
TelemetryKerberos, NTLM, DNS, and directory replication traffic — not endpoint processes.
Core detectionsPass-the-Hash, Pass-the-Ticket, Kerberoasting, Golden Ticket, overpass-the-hash, reconnaissance, DC sync, rogue DC, brute force, honeytoken use.
HoneytokenA decoy account or resource; any authentication against it is high-signal.
Lateral movement pathsShows how a compromised identity could reach tier-0 assets through existing logon relationships; use it to break the path.
Versus Entra ID ProtectionIdentity Protection = cloud sign-in risk. Defender for Identity = on-premises AD credential abuse.
ResponseDisable the account, reset the password twice for KRBTGT, remove sessions, rotate service account secrets.

Defender for Office 365

ItemWhat to remember
Safe LinksTime-of-click URL evaluation and rewriting. Covers email, Teams, and supported Office clients.
Safe AttachmentsSandbox detonation; Dynamic Delivery sends the body while the attachment is still being analysed.
ZAPZero-hour auto purge removes or quarantines messages after delivery when a verdict changes to malware or high-confidence phish.
Threat ExplorerEmail hunting by sender, recipient, subject, URL, file hash; powers soft delete, move to quarantine, and campaign views.
AIRAutomated investigation for email: entity analysis, cluster analysis, and a recommended action (purge, block sender, etc.).
Attack simulationControlled phishing campaigns plus automated training assignment for users who click or submit credentials.
SubmissionsUser-reported and admin-submitted messages land in the Submissions queue for review and purge.

Defender for Cloud Apps

ItemWhat to remember
Cloud DiscoveryParses firewall/proxy/endpoint logs to find shadow IT, then matches apps to the catalog with a risk score (0–100).
SanctioningMark discovered apps sanctioned or unsanctioned to record the decision and drive reporting and blocks.
Session policiesReal-time controls (block download, block upload, protect on download) that require Conditional Access App Control.
File policiesScan files at rest in connected apps; match labels or sensitive info types; remove external sharing, quarantine, alert.
App governanceOAuth app inventory, permissions, publisher, consent grants; policies can alert, disable, or revoke an overprivileged app.
Anomaly detectionBuilt-in policies for impossible travel, unusual inbox rule, mass download, suspicious OAuth app, ransomware activity.
Connector typesAPI connectors (app audit and files) versus Conditional Access App Control (proxy, real-time session).

Defender for Cloud

ItemWhat to remember
PurposePosture management (CSPM) plus workload protection across Azure, AWS, GCP, and on-premises.
Secure scoreWeighted posture score with prioritised recommendations; not an incident or threat measure.
To SentinelConnect with the Defender for Cloud connector and choose which alert types stream into the workspace.
Cloud-native alertsControl-plane and data-plane detections, attack-path analysis, and agentless scanning.

Exam tip: when a question asks where the correlation happened, the answer is Defender XDR; when it asks where the detection logic lives, match the workload to its telemetry.

Platform and roles

ItemWhat to remember
What Sentinel isCloud-native SIEM with SOAR built in, running on a Log Analytics workspace.
Data boundaryThe workspace holds the logs; Sentinel adds connectors, rules, incidents, and automation on top of it.
Multiple workspacesWorkspace manager for many workspaces you own; Azure Lighthouse for cross-tenant (MSSP) delegation.
Cross-workspace queryworkspace('name').Table — needs read access to the other workspace.
RolesSentinel Reader (view) · Sentinel Responder (manage incidents) · Sentinel Contributor (author content) · Playbook Operator (run playbooks) · Sentinel Automation Contributor (lets Sentinel attach playbooks to rules).
Key tablesSigninLogs, AuditLogs, SecurityEvent, SecurityAlert, SecurityIncident, OfficeActivity, CommonSecurityLog, Syslog, Heartbeat, ThreatIntelligenceIndicator, BehaviorAnalytics, Watchlist.

Connectors and ingestion

ItemWhat to remember
Content hubInstalls solutions: connectors, rule templates, workbooks, hunting queries, parsers, playbooks.
Azure ActivitySubscription control-plane operations (resource deletion, role assignment changes).
Microsoft Entra IDSigninLogs (interactive and non-interactive sign-ins) and AuditLogs (directory changes).
Microsoft 365OfficeActivity — Exchange, SharePoint, OneDrive, Teams audit events.
Defender XDRStreams alerts and incidents. For integrated products, disable Microsoft incident creation rules so one attack does not create two incidents.
CEF / SyslogVia the Azure Monitor Agent on a Linux forwarder; then normalise with ASIM parsers.
Logs Ingestion APIFor sources with no connector: data collection endpoint + DCR + custom table.
TAXIIPulls STIX indicators from a provider into ThreatIntelligenceIndicator.
DCR purposeSelects what is collected, transforms/filters it, and names the destination table — filter before ingestion to cut cost.
ASIMNormalisation layer: one schema, one parser per source, so one query works across many vendors.

Retention, plans, and cost

ItemWhat to remember
Analytics retention30 days to 2 years (730 days); fully queryable by rules and hunting.
Total retentionMirrors data to the data lake for up to 12 years; by default equals analytics retention.
Interaction with long-termOlder data is reached with search jobs, restore, or data lake queries — not always-on analytics rules.
Table plansAnalytics (real-time detection), Basic (cheap, 30-day single-table queries for troubleshooting), Auxiliary (low-touch verbose/audit data).
Commitment tiersDiscounted ingestion at a committed daily volume; unused commitment is still billed.
Cost leversDCR filtering, table plan choice, retention split, commitment tiers, dropping noisy verbose tables.

Analytics rules

ItemWhat to remember
ScheduledYour KQL + frequency + lookback. Lookback must cover frequency plus expected ingestion delay.
NRTNear real time, minimal latency (roughly per-minute), simple query, no custom schedule.
FusionMicrosoft's multistage correlation engine; enabled by default, no query to author.
Microsoft SecurityCreates incidents from alerts raised by connected Microsoft security products.
ML behavior analyticsMicrosoft-trained models for anomalous behaviour; no query.
AnomalyInformational anomaly alerts from ML models; tunable, not automatic incidents.
Threat intelligenceMatches ingested indicators against telemetry.
Entity mappingMaps result columns to Account, Host, IP, File, Process, CloudApplication, DNS, URL — this is what makes pivots and the graph work.
Custom detailsNamed key/value fields surfaced on the alert for context.
Alert groupingCombines alerts from one rule into one incident, by time window and/or entity.
SuppressionStops the query running for a period after an alert; reduces alert volume.
Incident creationCan be turned off per rule, leaving alerts in SecurityAlert for query-based triage.
MetadataSeverity, tactics and techniques (MITRE ATT&CK), description, and entity mappings drive triage and coverage reporting.

Automation

ItemWhat to remember
Automation ruleNo-code triage: conditions on incident/alert, then assign owner, change status/severity, add tags, run playbook. Runs in order, can stop processing.
PlaybookAn Azure Logic App triggered by an incident or alert; calls connectors (Teams, ServiceNow, email, Graph, HTTP).
Playbook permissionsSentinel runs incident-trigger playbooks under a service identity that needs rights on the playbook's resource group; Sentinel Automation Contributor attaches playbooks to rules.
Trigger typesWhen an incident is created · when an alert is created · manual run from the incident.
Design patternAutomation rule decides who/what/when; the playbook performs the external actions.

Hunting and investigation

ItemWhat to remember
Hunting loopHypothesis → query → findings (bookmarks, entities) → investigation → promote to detection.
BookmarkPreserves a query and its exact results; tag it, add to an incident, investigate in the graph.
LivestreamInteractive continuous query that surfaces new matches as they arrive.
Search jobAsynchronous sweep over long-term/archived data; results land in a new table.
RestoreBrings a chosen time window of archived data back to the analytics tier for full KQL.
Entity pageConsolidated alerts, incidents, activity, and UEBA insights for one user, host, or IP.
Investigation graphEntity-centric pivoting across alerts, events, and bookmarks.
MITRE pageCoverage of active rules and hunting queries by tactic and technique, with gap analysis.
Bookmarks vs watchlistsBookmarks are evidence; watchlists are reference lists.

UEBA, watchlists, workbooks, and intel

ItemWhat to remember
UEBAEnabled per workspace; needs identity plus activity data. Builds behaviour profiles, peer-group comparison, and anomaly scores.
BehaviorAnalyticsTable holding UEBA-derived activity and anomaly records; entity pages surface the insights.
WatchlistsImported reference lists (VIPs, scanners, high-value assets) used in queries via _GetWatchlist('name') or the Watchlist table.
Threat intelligenceIndicators in ThreatIntelligenceIndicator; match telemetry with a join, or use the TI matching rule type.
WorkbooksInteractive reports built on queries, with parameters for time range and filters.
Incident tasksChecklist items that record and assign response steps on an incident.

Exam tip: choose the rule type by what triggers it — your query (scheduled/NRT), Microsoft correlation (Fusion), a connected product (Microsoft Security), or a model (ML/anomaly).

SC-200 cheat sheet 3/5 — KQL for detections

One page. Facts snapshot 2026-11; verify current behaviour on Microsoft Learn before the exam.

Query shape

ItemWhat to remember
AnatomyTable | operator | operator ... — each operator consumes the previous result set, left to right.
Order mattersYou can only reference a column after the operator that creates it: summarize Failed = count() by User then extend High = Failed > 20.
Time filter firstwhere TimeGenerated > ago(24h) prunes before later operators run. ago() accepts 5m, 1h, 7d, 30d; absolute times use datetime(2026-11-01).
searchsearch "term" scans many tables and is expensive; prefer a named table.
letBinds scalars, tables, or functions for reuse: let since = 7d; let vip = _GetWatchlist('VIP') | project SearchKey;

Core tabular operators

OperatorEffect
whereFilter rows with a Boolean expression.
project / project-awayKeep (and order) named columns, or remove named columns and keep the rest.
extendAdd calculated columns; original columns stay.
summarizeGroup and aggregate: summarize count() by Col. Result has only the group and aggregate columns.
sort by / order by / top N byOrder rows (desc); top N by sorts and limits in one step.
take N / limitReturn N arbitrary rows — no ordering guarantee.
distinctUnique combinations of the listed columns.
joinMatch rows sideways on a key (kind= controls the join).
unionStack rows from tables/queries with compatible columns.
lookupEnrich with a dimension table, keeping the left side only.
parseExtract with a literal pattern: parse Raw with "User=" User " Action=" Action.
extractExtract with a regex and capture group: extract(@"id=(\d+)", 1, Url).
mv-expandOne row per element of a dynamic array.
bin(Col, 1h)Bucket a timestamp or number; use inside summarize for time series.
renderVisualise (timechart, barchart, piechart, table). Last operator in the query.

Aggregations

FunctionReturns
count()Number of rows in the group.
countif(pred)Rows matching the predicate — one pass for several counters.
dcount(col)Approximate number of distinct values; add hll precision if needed.
sum, avg, min, maxNumeric aggregates; percentile(col, 95) for tail values.
arg_max(TimeGenerated, *)The whole row with the latest timestamp per group; arg_min for earliest.
make_set(col)Dynamic array of distinct values in the group.
make_list(col)Dynamic array of all values, duplicates included.

Strings, types, and comparisons

ItemWhat to remember
has / has_csWhole-term match, indexed and fast ("mimikatz" matches on token boundaries).
contains / contains_csSubstring match; slower, matches inside other words.
startswith, endswithPrefix and suffix tests.
matches regexRegular expression match; most expensive of the set.
in (…), !in (…)Membership test; ideal for lists and subqueries.
between (a .. b)Inclusive range test.
Case sensitivityUnadorned operators are case-insensitive; the _cs suffix makes them case-sensitive.
tostring()Convert a dynamic scalar to string before comparing or displaying.
todynamic() / parse_json()Convert a JSON string into a dynamic object; read keys with dot notation (AdditionalFields.OSVersion), and arrays with [0] or mv-expand.
isempty(), isnull()Test for empty string or null; KQL uses == for equality, never =.

Joins

ItemWhat to remember
Default kindinnerunique — deduplicates the left key; use kind=inner when every left row must survive.
Kindsinner, innerunique, leftouter, rightouter, fullouter, leftanti, leftsemi, anti, semi.
leftantiLeft rows with no match — perfect for "users with no MFA".
leftsemiLeft rows that do have a match, without duplicating columns.
Column clashPrefix with $left. and $right.; project before the join to avoid ambiguity.

Performance rules

RuleWhy
Filter before extend, summarize, joinFewer rows carried through expensive operators.
project earlyFewer columns means less memory and less shuffle.
Prefer has over containsTerm matching uses the index.
Avoid search *Full-workspace scans are the most expensive pattern.
Use materialize()Cache a subquery reused several times in one query.

Patterns worth memorising

GoalPattern
Top talkerssummarize N = count() by UserPrincipalName, then top 10 by N desc
Latest row per entitysummarize arg_max(TimeGenerated, *) by DeviceName
Threshold on a groupsummarize Files = count() by UserId, bin(TimeGenerated, 1h), then where Files > 500
Exclude a watchlistwhere UserPrincipalName !in the watchlist's SearchKey values
IOC matchjoin kind=inner network events to ThreatIntelligenceIndicator on the IP column

Exam tip: read a query inside out — filter, aggregate, sort, limit — and remember where on an aggregate must come after summarize.

Incident response phases

PhaseWhat happensSC-200 tools
PreparePlaybooks, detection coverage, access tiers, communication plan.Automation rules, incident tasks, Sentinel content hub.
Detect and triageValidate, classify, assign, scope the affected entities.Incident queue, attack story, entity pages, UEBA.
ContainStop spread across every compromised path: endpoint, identity, app, network.Device isolation, session revocation, password reset, indicator block, playbook.
EradicateRemove malware, persistence, web shells, rogue accounts, vulnerable entry points.Live response, AIR, ASR rules, patching.
RecoverRestore service, verify clean, monitor for reinfection.Backups, tamper protection, watchful rules.
Lessons learnedTimeline, root cause, detection gaps, control changes.Rule tuning, new detections, playbook changes.

Triage and scoping

ItemWhat to remember
First questionIs this real, and how far has it spread? Scope before you contain.
Scope by campaignIdentify every recipient, click, device, and account touched — not just the first report.
Correlate entitiesUsers, hosts, IPs, mailboxes, apps, and cloud resources appear in the attack story and graph.
Identify the entry pointPhishing, exposed service, valid credentials, or a supply chain — recovery fails without this.
Business contextAsset value, data classification, regulatory obligation, and blast radius of the response itself.
Severity disciplineHigh severity is for urgent, high-impact items; over-grading destroys queue meaning.

Containment actions by workload

WorkloadActions
EndpointFull isolation · selective isolation (allow list) · restrict app execution · live response · antivirus scan · collect investigation package · initiate automated investigation.
IdentityDisable account, revoke refresh tokens/sessions, reset password, require re-registration of MFA, remove device compliance, block sign-in.
EmailSoft delete or hard delete messages, move to quarantine, block sender/URL, purge campaign from all mailboxes, disable forwarding rules.
Cloud appRevoke OAuth consent, disable the enterprise app, remove delegated permissions, session policy block.
NetworkBlock IP/URL/hash indicator, close the exposed port, restrict with Conditional Access or firewall policy.
Domain (AD)Reset the account, reset KRBTGT twice after a Golden Ticket, rotate service account passwords, remove rogue DCs.

Evidence and forensics

ItemWhat to remember
Order of volatilityCPU/cache and memory → running processes and network connections → disk → remote logs → backups.
Chain of custodyWho collected what, when, from where, hash, storage location, and every transfer or access.
HashingHash on collection and re-verify at analysis; a broken chain can invalidate evidence.
Investigation packageDefender for Endpoint forensic snapshot — collect before reimaging or wiping.
TimelineNormalise every source to one time zone (UTC) and order chronologically before drawing conclusions.
Log sourcesSign-in and audit logs (identity), mailbox audit (email), endpoint tables (device), firewall/proxy (network), cloud app audit (SaaS).
RetentionAnalytics 30 days–2 years; long-term up to 12 years via search job or restore when the investigation spans months.
Legal holdBlock sign-in but hold the mailbox and files; never delete when a tribunal or regulator may need them.

Attack patterns

PatternSignatureResponse
Password sprayOne or few passwords against many accounts, low attempt count each.Block source, require MFA, reset any successes, review sign-in risk.
Brute forceMany passwords against one account.Lockout, block IP, reset, check for success after failures.
Credential stuffingReplayed breached user/password pairs across sites.Force reset, check breach exposure, enable MFA.
Pass-the-HashNTLM hash reused; no password needed.Reset the account, reset machine account, hunt for LSASS access.
Pass-the-TicketValid Kerberos ticket reused.Revoke tickets, reset account, review delegation.
KerberoastingBurst of service-ticket requests, often RC4, cracked offline.Rotate service account passwords to long managed secrets, review SPNs.
Golden TicketForged TGT signed with KRBTGT; long lifetime.Reset KRBTGT twice, reset privileged accounts, rebuild trust.
Business email compromiseHidden inbox rule, forwarding, payment or payroll change requests.Remove rules, revoke sessions, reset password, purge messages, notify finance.
Illicit OAuth consentApp granted mail or file permissions, often from a phishing lure.Revoke consent, disable app, remove rules, reset credentials.
RansomwareMass file rename/encryption, shadow copies deleted, ransom note.Isolate, disable accounts, preserve evidence, find entry point, restore from clean backup.
Command and controlRegular small beacons to a rare domain or IP.Isolate, block indicator, identify the spawning process.
Insider data theftOff-hours mass download, personal cloud upload, departing employee.Preserve evidence, involve HR and legal, DLP and Cloud Apps evidence, litigation hold.
Impossible travelTwo distant sign-ins in a short window.Rule out VPN/proxy egress before declaring compromise.

After-action work

ItemWhat to remember
MeasureTime to detect, time to contain, scope accuracy, and percentage of incidents auto-triaged.
Close the gapEvery missed behaviour becomes a new or tuned analytics rule, tested before enabling.
Tune safelyAdd exclusions with justification; never disable a rule wholesale to silence noise.
DocumentIncident summary = timeline + affected entities + root cause + actions + residual risk.
CommunicateA defined plan with named roles, cadence, and escalation to legal and regulators.

Exam tip: exam scenarios reward sequence — validate, scope, contain, eradicate, recover, review. Answer choices that skip a step are usually wrong.

Common distractors

TrapCorrection
"Defender for Endpoint correlates email and identity alerts"It does not; Defender XDR is the correlation layer.
"Sentinel replaces Defender XDR correlation"Sentinel aggregates; XDR correlates the workload signals first.
"Suppression reduces incident count"Suppression reduces alerts; grouping reduces incidents.
"Grouping and suppression are the same"Different features with different effects — read the verb in the stem.
"Alert grouping stops the query running"Only suppression does that.
"Isolate then offboard the device"Offboarding removes telemetry and evidence; never a containment step.
"Delete the account to contain a compromise"Disable and revoke sessions; deletion destroys evidence and may be reversible only for 30 days.
"Restore from backup and put the server back"Reinfection is almost certain until the entry point and credentials are fixed.
"A scan proves the device is clean"It does not; collect evidence and rebuild.
"Enable every incident-creation rule for Defender products"Duplicate incidents — disable Microsoft incident creation for integrated products.
"Increase retention to fix a slow query"Retention changes storage, not query cost; bound the time range.
"NRT accepts any query complexity"NRT is for simple, low-latency queries.
"Fusion uses your query"Fusion does not accept custom queries.
"A watchlist stores detection logic"Watchlists store reference data.
"Isolating a device blocks live response"Full isolation still allows live response and the Defender service.
